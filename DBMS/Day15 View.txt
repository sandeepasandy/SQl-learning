--What is view?
View is a virtual table in MySQL.but from the result of a stored select statement.It looks
and behaves like a regular table when you query it.You can select from it,filter it,and join it.
but it doesn't store any data of its own,every time a view is queried,MySQL runs its underlying selct statement
against the real tables and returns the result

--Why do we need Views?
Simplify complex queries :Hide multi-table joins,subqueries and calculation behind a single,simple table like name.
reuse query logic:write a complex select once and reuse it anywhere,reports applications,dashboards without copy
pasting SQL
Data Security:Expose only specific columns or rows to certain users,without granting them access to full base table
Different perspectives of the same data:Different departments can have their own tailered views of the same underlying tables
Logic and independence:If the underlying table structure changes slightly.you can often adjust just view 
defintion and keep all dependent queries working changed
Simplifying reporting:Pre-packing aggregations(total,average,counts)into a view so business users can query them without 
knowing SQL

--Advantages
Security:Restrict access to sensitive columns (eg:salary)or sensitive rows(only a users own department).
Simplicity:End users and applications interact with simple named virtual table instead of complex SQL
Reusability:one view definition can be reused across many reports,applications
Consistency:Bussiness logic(calculation,filter)lives in one place,so results are always consistent.
Maintainablity:A bussiness rule change only need to be made once.inside the view
Custom data Presentation:rename or reformat columns and computed columns without touching the base table
No extra storage cost:A standard view stores no data-->only its query definition

--Creating views
--syntax:
create view view_name as 
select columns
from tables
where conditions;

--Altering views:
--syntax:
alter views view_name as
select new_columns
from new_tables
where new_conditions;

--dropping views:
--syntax:
drop view view_name;

--CREATING VIEW:

CREATE VIEW VW_EMPLOYEE_DEPARTMENT AS
SELECT E.EMP_ID,E.EMP_NAME,E.DESIGNATION,D.DEPT_NAME,D.LOCATION
FROM EMPLOYEES E
JOIN DEPARTMENTS D
ON E.DEPT_ID=D.DEPT_ID;

SELECT*FROM VW_EMPLOYEE_DEPARTMENT;

TCL COMMANDS
------------
1.COMMIT: DIRECTLY SAVED IN THE DATABASE
AFTER COMMIT ROLLBACK DOES NOT WORK

2.ROLLBACK:IT WILL GO TO THE BEFORE TRANSACTION

3.SAVEPOINT:
SAVEPOINT is used to create a temporary point within a transaction, so that we can roll back the transaction
to that point without rolling back the entire transaction.

Transactions definition:
------------------------
The process of combining all related operations into a single unit and executing them according to the 
rule "either all operations should succeed or none should succeed"is called transaction management.

Ex:funds transfer
consider a money transfer process between two accounts

1.debit amount from the senders account
2.credit amount into the receivers account

There are two types of transactions such as
1.Local Transactions
--------------------
in local transactions all operations of a transaction are executed on the same database
ex: funds transfer from one account to another account where both accounts belong to the same bank
2.Global transaction
--------------------
In global transactions,operations of a transaction are executed on different databases
ex:
Funds transfer from one account to another account where both accounts belong to differnt banks
 
ACID Properties:
---------------
A-->Atomicity:all or none
C-->consistency:The database remains in a valid state
I-->Isolation:Transactions do not interface with each other
D-->Durability:committed changes are permanent
